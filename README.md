# مَسَارُك — بيانات المشهد (scenes.json)

هذا الملف يشرح كيف يُولَّد ملف بيانات القصة `scenes.json`، وكيف يُتحقَّق من صحته آليًا.

## الملفات في هذا المجلد

| الملف | الدور |
|---|---|
| `scenes.json` | الملف الناتج النهائي — كل مشاهد القصة (P0, C1–C12, EVAL, E1–E4, GROWTH_REPORT) بصيغة يمكن لمحرك لعبة قراءتها مباشرة. |
| `scenes.schema.json` | مخطط JSON Schema (معيار 2020-12) الذي يحدد الشكل الصحيح لـ `scenes.json` — الحقول المطلوبة، الأنواع، القيم المسموحة. |
| `build_scenes_json.py` | سكريبت التوليد. يبني `scenes.json` من الصفر ثم يتحقق منه تلقائيًا مقابل `scenes.schema.json`. |
| `validate_scenes_json.py` | سكريبت فحص مستقل، يُشغَّل على `scenes.json` الموجود دون إعادة توليده. |
| `simulate_endings.py` | مصدر الحقيقة الرقمي: القيم الابتدائية للسمات، تأثيرات كل خيار في كل فصل، منطق تحديد النهاية (`resolve_ending`). كل الأرقام في `scenes.json` مسحوبة من هنا برمجيًا، لا مُعاد كتابتها يدويًا. |
| `build_masarak_dialogue.js`, `build_masarak_dialogue_c5_c12.js`, `build_masarak_endings.js` | مصدر النص السردي الكامل بالعربية (الحوار، السرد، أزرار القرار) لكل فصل ونهاية. |
| `ending_simulation_report.json` | آخر نتيجة محاكاة شاملة لِـ 354,294 مسارًا محتملًا عبر الفصول الاثني عشر. |

## طريقة توليد scenes.json

```bash
python3 build_scenes_json.py
```

عند التشغيل، السكريبت يقوم بالتسلسل التالي:

1. يستورد `simulate_endings.py` برمجيًا (عبر `importlib`) ليأخذ منه القيم الابتدائية للسمات السبع، وتأثيرات كل خيار في كل فصل، وأعلام التخفيف، ومنطق تحديد النهايات — بدل إعادة كتابتها يدويًا في مكانين قد يختلفان.
2. يبني بنية `meta` (تعريف السمات، ترتيب الفصول والمشاهد، الأفعال الثلاثة، أولوية النهايات...) وبنية `scenes` (كل مشهد بنصه الكامل وبطاقة قراره وتأثيراته الرقمية).
3. يكتب الناتج إلى `scenes.json` مع رابط `"$schema": "./scenes.schema.json"` في أوله.
4. **يتحقق تلقائيًا** من الملف الذي كتبه للتو مقابل `scenes.schema.json`. إذا وُجد أي تعارض — حقل محذوف أو مُعاد تسميته بالخطأ، نوع بيانات غير صحيح، مشهد ناقص أو زائد — يوقف السكريبت التنفيذ بخطأ صريح يعرض كل المخالفات بدل أن يترك ملفًا فاسدًا على القرص بصمت.

الناتج المتوقع عند النجاح:

```
scenes.json written. scene count: 19
Schema check passed: scenes.json conforms to scenes.schema.json.
```

## طريقة التحقق من scenes.json في أي وقت

لفحص ملف `scenes.json` موجود دون إعادة توليده (مثلًا بعد تعديل يدوي، أو للتأكد الدوري):

```bash
python3 validate_scenes_json.py
```

هذا السكريبت يشغّل طبقتين من الفحص معًا:

**الطبقة الأولى — الفحص البنيوي (المخطط):**
يتحقق من أن `scenes.json` يطابق `scenes.schema.json` تمامًا: كل الحقول المطلوبة موجودة، الأنواع صحيحة، رموز السمات (K/D/C/B/R/M/P) ورموز النهايات (E1–E4) ضمن القيم المسموحة، وأن الفصول الخاصة (C9 وC10) تحمل الحقول الإضافية المطلوبة لها (`branchMap`، `conditionalBeats`، `modifiers`).

**الطبقة الثانية — الفحص المنطقي (المحاكاة):**
يعيد بناء محاكاة كاملة لكل الفصول الاثني عشر (354,294 مسارًا) باستخدام الأرقام المُخزَّنة داخل `scenes.json` فقط، ويقارن توزيع النهايات الناتج بتوزيع `simulate_endings.py` الأصلي. تطابق تام يعني أن الملف يمثّل منطق القصة بدقة، لا نصًّا منفصلًا عنه.

الناتج المتوقع عند النجاح:

```
SCHEMA CHECK: passed (scenes.json conforms to scenes.schema.json)
Re-simulation from scenes.json ONLY:
  E1: 2611 / 354294 (0.737%)
  E2: 35094 / 354294 (9.905%)
  E3: 95450 / 354294 (26.941%)
  E4: 221139 / 354294 (62.417%)
MATCH: scenes.json reproduces the exact same ending distribution as simulate_endings.py

All validation checks passed.
```

إذا ظهرت رسالة `SCHEMA CHECK: FAILED` أو `VALIDATION ERRORS`، يعرض السكريبت موضع كل خطأ (اسم المشهد/الحقل) ووصفه، لتصحيحه قبل استخدام الملف.

## المتطلبات

- Python 3
- حزمة `jsonschema` (تُثبَّت تلقائيًا عبر `pip install jsonschema` إذا لم تكن موجودة — كلا السكريبتين يتحققان من وجودها ويثبّتانها بنفسه عند الحاجة).

## عند تعديل محتوى القصة

- **تعديل نص حوار أو خيار حالي:** عدّل ملفات JS المصدرية (`build_masarak_dialogue*.js` أو `build_masarak_endings.js`) إن كان التعديل نصيًا فقط، أو عدّل البنية المقابلة مباشرة داخل `build_scenes_json.py` إن كان التعديل في `scenes.json` نفسه.
- **تعديل أرقام (تأثيرات خيار، عتبة نهاية، علم تخفيف):** يجب أن يبدأ التعديل من `simulate_endings.py` أولًا (مصدر الحقيقة الرقمي)، ثم إعادة توليد `scenes.json` عبر `build_scenes_json.py` — وليس تعديل الأرقام داخل `scenes.json` مباشرة، لأن ذلك سيفصله عن المحاكاة المرجعية.
- **تعديل بنية الملف نفسها (إضافة حقل جديد لمشهد، مثلًا):** حدِّث `scenes.schema.json` ليعكس البنية الجديدة **قبل** إعادة التوليد، وإلا فسيرفض الفحص التلقائي الملف الناتج.

بعد أي تعديل، الخطوة الأخيرة دائمًا:

```bash
python3 build_scenes_json.py && python3 validate_scenes_json.py
```
